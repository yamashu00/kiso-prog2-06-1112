## 「材料」と「結果」の違い（大事）

| | どんなファイル？ | 例 |
|---|---|---|
| **材料** | 最初から配布しているファイル。gcc に読み込ませる | 01-include.c、sample.txt |
| **結果** | `gcc -E ... -o ○○.i` を実行したときに、自分で作るファイル。プリプロセス（#include や #define の置き換え）が終わったあとの姿 | 01-include.i |

- **.i ファイルは、中身を見て確かめるためだけのファイルです。** 編集したり、#include したりしないでください。
- .i ファイルの中には、stdio.h の中身も main も全部入っています。#include すると同じものが二重になり、エラーになります。

## よく使うコマンド

```
gcc 01-include.c -o 01-include          いつものコンパイル（実行ファイル 01-include ができる）
./01-include                            実行する

gcc -E 01-include.c -o 01-include.i     プリプロセスだけ実行して、結果を 01-include.i に保存する
tail -n 12 01-include.i                 01-include.i の最後の12行だけを画面に表示する
wc -l 01-include.i                      01-include.i の行数を数える
```

## 注意

- Mac で `gcc` と打つと、中身は Apple の clang というコンパイラが動きます（`gcc --version` で確認できます）。使い方は同じです。
- `.i` ファイルの行数や、`# ` で始まる目印の行の数字は、パソコンの種類によって違います。隣の人と少し違っても問題ありません。
- 「作成」のファイルは、書き換える前でもコンパイル・実行できます（結果は 0 などになります）。
